# 当天信息去重评测

本测试集用固定材料检查模型的实际判断。运行器调用生产 `backend.deduplicate()`，不会收集候选、抓取网页、生成摘要、更新推荐历史或发布简报。与使用模拟判断的流程测试不同，这里可以发现真实模型的语义错误。

默认运行 [`cases-v2.json`](./cases-v2.json)，包含 10 例。最初的 7 例保存在不可变的 [`cases.json`](./cases.json)（V1）；V2 保留原始输入，明确记录评测暴露情况，并纠正一项已裁定的期望。

| 案例 | 期望 |
| --- | --- |
| PHP 安全公告、发布说明、基金会分析 | 公告与发布说明重复，基金会分析保留；这是开发回归案例 |
| 大桥重开简讯与详细工程报告 | 两种输入顺序都保留详细报告 |
| 同场旱灾的经济影响与植物机制 | 两篇各有独立信息，都保留 |
| 同一博物馆的扩建与文物归还 | 不同事件，都保留 |
| 材料不足的两个研究记录 | 无法确认重复，都保留 |
| 水质报告及更正 | V2 只保留完整更正，旧简讯的全部事实已包含其中；V1 原期望保留两篇，已归档 |
| 铁路重开简讯、故障分析、运营方案 | 简讯可由任何一篇实质文章覆盖；两篇实质文章都保留，不能传递合并 |
| 藻华的水质测量与渡轮调整 | 同一环境事件、不同实质信息，都保留（V2 新例） |
| 音乐会取消简讯与完整通知 | 完整通知覆盖简讯并补充安全原因和退款办法，只保留完整通知（V2 新例） |
| 两个雀鸟颜色学习实验 | 方法和结果各有独立信息，都保留（V2 新例） |

PHP 材料只保存公开简报中的标题、链接和已生成摘要；不提交真实文章正文。默认的 PHP 摘要材料实验缺少原文，只是探索性结果，输出中标为 `authoritative: false`；生产规则在证据不足时保留，所以不能把摘要材料实验中的保留直接当作可靠的判重失败。权威 PHP 回归需要下述显式本地正文。其余材料都是作者编写的合成案例，不依赖外部服务或真实文章。这是一个很小的初始集合，不代表日常准确率。PHP 已用于开发，不能计作独立留出成绩。后续如果根据某个留出失败调整提示词，该例也应改记为开发回归，并补充新留出案例。

V2 按实际暴露历史分为三个组，结果必须分开报告：

- `development_regression`：PHP、大桥、材料不足、水质更正，共 4 例。前两项语义问题及材料不足问题已被用于讨论提示词；水质更正则涉及 gold 重新裁定。
- `previously_evaluated_untuned`：旱灾、博物馆、铁路，共 3 例。已在 V1 实测，未用于这轮提示词调整，也不能再称为首次留出。
- `first_view_v2_holdout`：藻华、音乐会、雀鸟，共 3 例。输入和期望在第二轮实测前冻结，未参照修改后的生产提示词编写，也未提供给提示词编写者。

水质期望的重新裁定依据是材料覆盖：更正文章明确复述了初始 80 mg/L 读数和饮水禁令，并补充单位换算错误、8 mg/L 正确值、独立复测和解除禁令。初始简讯没有独立剩余信息，因此只保留更正。这不表示所有更正都应删除初始分析。V1 文件、旧 gold 和原成绩不会追溯改写。

每个案例使用原顺序、反顺序，各重复 3 次，V2 默认共 60 次逻辑调用；V1 为 42 次。两种顺序共享同一份语义期望，详细文章不能仅因排在后面而丢失。期望指定完整保留集合与每个删除项允许指向的单篇保留文章；允许多个合理目标不等于允许把几篇文章合起来覆盖删除项。运行器只把候选的标题、摘要、证据和链接传给生产后端，期望、解释和案例分类不会进入模型输入。

在项目根目录按根 README 的方式安装并加载环境配置，然后运行：

```sh
python scripts/evaluate_content_deduplication.py \
  --output data/content-dedup-evaluations/baseline-v2.json
```

默认使用已配置的分类模型、生产提示词和材料截取规则。运行器将短重试设为 0；可通过 `--max-retries 1` 或 `2` 显式增加。`--max-requests` 默认 100，按案例数 × 两种顺序 × 重复次数 ×（重试数 + 1）预先检查传输尝试上限。最多允许 10 次重复和 600 次传输尝试。去重调用暂停日常运行的长时间网络恢复。

OpenRouter 继续使用后端原有的运行预算，`--budget-usd` 默认 $0.25（最高 $5），如果环境中的预算更低则取更低值。预算包含失败请求的保守预留。Gemini 后端没有美元预算功能，因此只能通过次数和短重试上限控制；费用字段可能为 null，运行器不自行推算费率。

如需用本地已保存的 PHP 正文做单独对照，必须显式指定忽略目录：

```sh
python scripts/evaluate_content_deduplication.py \
  --php-evidence-dir data/investigations/2026-10-22-content-dedup \
  --output data/content-dedup-evaluations/local-php-evidence-v2.json \
  --budget-usd 0.10
```

目录需包含 `50172041-article.txt`、`50180873-article.txt`、`50182987-article.txt`。不指定时不会读取它们；指定缺失目录或文件会失败。运行器不联网补材料。结果文件和可选正文目录都必须位于项目忽略的 `data/` 内，因为结果包含实际模型提示词，可能含私有证据。带正文的结果和默认摘要材料结果应分开报告。

JSON 结果记录输入及实际提示词的 SHA-256、生产系统指令快照、模型、输入顺序、期望、实际判断、耗时、可用的 token／费用／尝试次数，以及按案例和顺序统计的通过数与保留集合一致性。每个 `run`、`case_stats` 都记录 `evaluation_group`，顶层 `group_stats` 分别统计三组；V1 没有该字段时回退为原 `category`。未知费用或尝试次数为 null；异常只记录类型和结构化错误码，不保存供应商异常消息。HTTP 尝试计数包括后端短重试。成功生成格式合法的判断也可能语义失败；进程在存在语义失败或调用错误时返回 1，全部通过返回 0。

比较版本时固定案例文件和正文来源，先报告逐案例、逐顺序结果，再比较重复运行的稳定性。不要用“保留集合一致”代替正确性：模型可能两种顺序都稳定地犯同一个错误。

运行器的确定性测试不使用凭据或真实服务：

```sh
pytest -q tests/test_content_deduplication_evaluation.py
```
